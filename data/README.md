# Positions benchmark

No public dataset exists for this task, so we build our own. Everything here is generated by code from fixed seeds and can be rebuilt with:

```bash
python experiments/build_dataset.py --config experiments/configs/dataset.yaml
```

## Contents

| File | What |
|---|---|
| `positions/dev.jsonl` | 60 positions for prompt iteration and debugging only |
| `positions/test.jsonl` | 180 positions for all reported experiments, stratified by difficulty (60 easy / 60 medium / 60 hard when available) |
| `positions/stats.json` | Counts by difficulty, source and situation tag; build configuration and time |
| `positions/hard_cases.yaml` | Hand-made hard cases with human-reviewed labels (to be added; see plan §9.4) |

## How positions are made

1. **Realistic mid-game states:** B2 (search bot) plays B1 (geometric bot) from seeded racks (`game_seed_start` onwards) at medium execution noise; two decision states are sampled from each game.
2. **Random placements:** 20 % of positions are random valid layouts (1–6 balls per side plus the 8, groups assigned).
3. Duplicates are removed by state hash. Positions with fewer than two candidate shots are dropped.
4. For each position the **frozen menu** is built once with the standard pipeline (access level L2, 8 noisy rollouts per candidate; up to 12 pots and 3 safeties). Each candidate keeps its geometry, its L1 preview and its L2 statistics. At evaluation time the same menu is described at L0, L1 or L2 by hiding fields, so all systems and all access levels judge exactly the same shots.
5. **Oracle:** every candidate gets an expected inning value (EIV) from 24 noisy executions, with the inning continued greedily by the B1 rule for up to 2 more shots (`src/cuemind/eval/oracle.py`). Regret = best EIV − chosen EIV.

## Record schema (one JSON object per line)

`position_id, split, source (midgame_sample | random | hand), difficulty (easy | medium | hard), tags (offense | position | defense), state (TableState), state_hash, prep, oracle_cfg, candidates_hash, candidates[] (Candidate with geometry, preview, rollouts), oracle {shot_id: {eiv, se}}, expected_intent, acceptable_shot_ids, reviewed_by`.

## Definitions

- **Difficulty** from the best pot probability in the menu: easy ≥ 0.80, medium 0.40–0.80, hard < 0.40.
- **Situation tags:** `position` when at least two pots have p_pot ≥ 0.6 and their next-shot ease differs by ≥ 0.3; `offense` when a good pot exists otherwise; `defense` when the best pot is below 0.4 or the opponent is on the 8. A position may have several tags.

## Limitations

The oracle is a short-horizon approximation of game value that uses a simple continuation policy; it is not the true game-theoretic value. Positions sampled from bot games follow the bots' style of play. The noise model is a simple Gaussian on aim, speed and tip offset.
